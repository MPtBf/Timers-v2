# Отчёт по делам (activity report) — правила оформления

Универсальная инструкция для агента: по запросу пользователя сформировать `.md`-отчёт
о времени по делам за **любой период** (день, 2 недели, всё время) и положить его во
временный файл. Основа — та же БД, что и у приложения (`blocks`), поэтому правила
одинаковы для любого периода: меняются только границы дат и постобработка.

Для получения отчёта агенту достаточно ссылки на этот файл:
`docs/activity-report-rules.md`.

---

## 1. Источник данных

- Файл БД: `C:\Users\ediko\AppData\Roaming\com.timers-v2.app\activity.db`
  (путь = `app_config_dir()` приложения Timers-v2, identifier `com.timers-v2.app`).
- Схема: `blocks(id INTEGER PK, name TEXT, start_ms INTEGER, end_ms INTEGER NULL)`.
  `start_ms`/`end_ms` — epoch milliseconds, локальный часовой пояс машины.
- **Только чтение.** Подключаться строго в режиме read-only:
  - python: `sqlite3.connect("file:...activity.db?mode=ro", uri=True)`
  - sqlite3 CLI: `sqlite3 -readonly "<path>"`
  Никаких `INSERT/UPDATE/DELETE/ALTER`, никаких миграций. Если пользователь просит
  «поправить данные» — он скорее всего имеет ввиду обработать .md отчё. Изменение базы данных 0 это отдельная задача и отдельное разрешение, не из этого отчёта.
- Открытый блок (`end_ms IS NULL`) считается по текущий момент (`now`).

## 2. Параметры периода

Пользователь задаёт период словами («за 16.09», «за последние 2 недели», «за всё
время»). Агент превращает его в два epoch-ms значения и фильтрует:

```sql
SELECT name, start_ms, end_ms FROM blocks
WHERE start_ms >= :from_ms AND start_ms < :to_ms
ORDER BY start_ms;
```

- Граница слева — включительно, справа — исключительно: `from = 16.09 00:00`,
  `to = 30.09 00:00` даёт период «с 16.09 по 29.09 включительно».
- «Всё время» = без нижней границы (но `from` в шапке = первый блок в БД).
- Блок, начавшийся до границы, но продолжающийся внутри периода, в отчёт **не**
  попадает (фильтр по `start_ms`). Если пользователь ждёт иное поведение — спросить.
- Все проценты считаются от суммы времени **выбранного периода**, не от всей БД.

## 3. Нормализация названий

Перед любыми слияниями:

1. `name.strip()`, привести к нижнему регистру, схлопнуть повторные пробелы.
2. Время дела = `end_ms - start_ms` (для открытого: `now - start_ms`).
3. Суммировать по нормализованному названию.

Регистр не различается: `HKT: 3` == `hkt: 3` == `hkt:  3`.

## 4. Слияния (обязательный шаг)

Слияние выполняется **до** порога «другие», иначе похожие дела разъезжаются по
строкам. Два механизма: таблица точных правил + авто-поиск внутри одного типа.

### 4.1 Точные правила (применять всегда, но проверять что лишнее не сливается)

| Было | Стало |
| --- | --- |
| `hachaton: …` (опечатка) | `hackaton: …` |
| `hlt` (опечатка) | слить в тип `hackaton` |
| `hkt` | слить в тип `hackaton` |
| `specrep` | `spacrep` |
| `souples` | `couples` |
| `concproc` | `conproc` |
| `chore: …` | `chores: …` |
| `conproc X` и подобные (без двоеточия) | `conproc: X` |
| `физи лаба` | `физи: лаба` |
| `conproc: ` (пусто) | `conproc` |
| `scam: potap voice` | `scam: voice` |
| `науч статья: …`, `науч статьи: …` | `науч: …` |
| `науч: статью с нуля` | `науч: статья` |
| `local qwen3 asr` | `local stt` |
| `rec: agents read` | `rec: agents book` |
| `rec: научные статьи` | `rec: read papers` |
| `базы: схему базы` | `уч: базы` |

Таблица также нужна для примерного представления о названиях и о том, что считается "одинаковым" и требует дополнительного ручного слияния.

### 4.2 Авто-слияние внутри типа

Внутри одного типа склеивать названия, у которых после удаления
пробелов/двоеточий/знаков препинания `SequenceMatcher.ratio() >= 0.93`.

### 4.3 Чего НЕ сливать

Одинаковый префикс — ещё не одинаковое дело. Запрещено склеивать различающиеся
суффиксы, даже если они похожи:

- `conproc: введ` ≠ `conproc: веро`
- `conproc: сети` ≠ `conproc: сист`
- `hkt: 1` ≠ `hkt: 2` ≠ `hkt: 3` … (нумерованные задачи — разные)

Если сомневаешься — не сливай и задай уточняющий вопрос пользователю с помощью question tool.

### 4.4 Слияние типов

Тип = первое слово названия (до пробела или двоеточия). Типы-опечатки тоже
сливаются: `hkt` → `hackaton`, отображение — `hackaton`. **Названия дел при этом
не переименовываются**: внутри одного типа `hackaton` спокойно лежат и `hkt: …`,
и `hackaton: …` — это одна строка типа, а не разные типы.

## 5. Оформление отчёта

### 5.1 Шапка

```markdown
# Отчёт по делам — Timers-v2

- Период: 16.09.2026 — 30.09.2026
- Всего: **48.2ч**, блоков: 137 (из них открытых: 1), уникальных названий: 61, после слияний: 54, типов и одиночных дел: 22
- Порог: дела меньше 2% от суммы времени своего типа свёрнуты в строку «другие»
- Проценты у дел — от общего времени, а не от типа
```

### 5.2 Тело: типы и дела

- Типы идут по убыванию суммарного времени.
- Формат строки типа: `- **имя**  Xч  Y%`.
- Вложенные дела: отступ **одним табом**, формат `\t- полное_название  Xч  Y%`.
- Часы — с одним знаком после запятой (`6.9ч`), проценты — с одним (`3.5%`).
- Порог «другие» у дел внутри типов: **2% от суммы времени своего типа** (не от общего!).
- **Одиночное дело**: строка типа = полное название дела, без вложенного дубля.

Пример (правильно):

```markdown
- **conproc**  26.9ч  13.5%
	- conproc: алго  4.7ч  2.4%
	- conproc: науч  2.7ч  1.4%
	- conproc: физи  2.6ч  1.3%
	- другие (3 дела)  1.2ч  0.6%
- **music player: add shazam playlist**  1.2ч  0.6%
- **spacrep**  12.1ч  6.1%
	- spacrep  11.6ч  5.8%
	- spacrep: eng  0.5ч  0.3%
- **local stt**  0.6ч  0.3%
```

Пример (нельзя):

```markdown
- **music**  1.2ч  0.6%
	- music player: add shazam playlist  1.2ч  0.6%             ← дубль одиночного дела
- **local**  0.6ч  0.3%             ← одиночное дело, обрезано, должно быть "local stt"
```

Если в типе несколько дел и все они ≥2% типа — строка «другие» не выводится.
Если ≥2% нет ни одного — выводится одна строка `\t- другие (N дел)  Xч  Y%`.

### 5.3 Подвал: слияния

Обязательный раздел — прозрачность: пользователь должен видеть, что именно склеено.

```markdown
## Слияния

- `concproc` → `conproc`
- `conproc алго` → `conproc: алго`
- `hkt: 1` → `hkt: 1 apply`
- `souples` → `couples`
- `науч: искать комнду` → `науч: искать команду`
```

Если слияний нет — написать `## Слияния` и `- не потребовались`.

### 5.4 Мини-пример из реального отчёта и разбор строк

Фрагмент настоящего отчёта (период «всё время», снято 26.09.2026, всего **199.9ч**).
Строки с `…` — пропущенные для примера подпункты ≥2% типа (в полном отчёте их больше):

```markdown
- **conproc**  27.0ч  13.5%
	- conproc: алго  4.7ч  2.3%
	- conproc: науч  2.7ч  1.4%
	- conproc: физи  2.6ч  1.3%
	- … ещё 9 дел ≥2% типа …
	- другие (3 дела)  1.2ч  0.6%
- **hackaton**  25.7ч  12.9%
	- hkt: проверка покрытия польз сценариев  6.9ч  3.4%
	- hkt: интеграционный smoke-суит  4.7ч  2.3%
	- hkt: 3  4.1ч  2.1%
	- hackaton: read info  0.7ч  0.3%
	- … ещё 8 дел ≥2% типа …
	- другие (7 дел)  2.1ч  1.0%
- **spacrep**  12.1ч  6.0%
	- spacrep  11.6ч  5.8%
	- spacrep: eng  0.5ч  0.3%
- **music player: add shazam playlist**  1.2ч  0.6%
- **local stt**  0.6ч  0.3%
```

Как эти строки получились:

1. `- **conproc**  27.0ч  13.5%` — тип = первое слово; сюда попали `conproc`,
   `conproc dev`, `conproc алго`, `concproc` и т.д. Порядок: 27.0 > 25.7 > 12.1,
   типы строго по убыванию. `27.0 / 199.9 = 13.5%` — процент от общего времени.
2. `\t- conproc: алго  4.7ч  2.3%` — слияние `conproc: алго` (3.1ч) + `conproc алго`
   (1.5ч) по правилу «`conproc X` → `conproc: X`»; показана, потому что
   `4.7 / 27.0 = 17% ≥ 2%` **от типа**.
3. `\t- другие (3 дела)  1.2ч  0.6%` — порог для типа `conproc` = 2% × 27.0ч =
   0.54ч; мельче него `conproc: ассесмент` (0.53ч), `conproc: конф` (0.43ч),
   `conproc: add extra prompt to script` (0.25ч) — они и свёрнуты. Число в
   скобках = сколько дел спрятано; `1.2ч` = их сумма; `0.6%` = от общего времени.
4. `- **hackaton**  25.7ч  12.9%` — слияние типов-опечаток `hkt` + `hackaton` +
   `hachaton` (+ `hlt` как опечатка `hkt`). Названия дел **не** переименованы,
   поэтому ниже соседствуют `hkt: …` и `hackaton: …` — это подпункты одного типа.
5. `\t- hkt: проверка покрытия польз сценариев  6.9ч  3.4%` — два разных
   процента: `6.9 / 25.7 = 27%` от типа (≥2% → показываем), а в строке `3.4%` =
   `6.9 / 199.9` от общего времени. Часы одинаковые, база для % разная.
6. `\t- hackaton: read info  0.7ч  0.3%` — прошла порог впритык:
   `0.7 / 25.7 = 2.7% ≥ 2%`; ещё чуть меньше — и попала бы в «другие».
7. `\t- другие (7 дел)  2.1ч  1.0%` — порог типа = 0.51ч; под него попали
   `hkt: созвон` (0.47ч), `hackaton: rules, models` (0.38ч),
   `hackaton: register, setup, read rules` (0.35ч), `hackaton: заметки об
   организации` (0.30ч), `hackaton: setup gitlab` (0.28ч), `hkt: 8` (0.28ч) и
   `hkt` (0.00ч) — ровно 7 дел.
8. `- **spacrep**  12.1ч  6.0%` / `\t- spacrep  11.6ч  5.8%` — `specrep` (0.45ч)
   слит в `spacrep` (11.1ч) по таблице слияний; строка `spacrep: eng` (0.5ч)
   показана, потому что `0.5 / 12.1 = 4.1% ≥ 2%` от типа — при глобальном пороге
   (0.3% от общего) она бы ошибочно спряталась.
9. `- **music player: add shazam playlist**  1.2ч  0.6%` — одиночное дело: строка
   типа содержит **полное** название, вложенного дубля нет.
10. `- **local stt**  0.6ч  0.3%` — `local`, `local qwen3 asr` слиты в `local stt`
    (одна запись) → тоже одиночное дело, полное название.

Числа приведены для конкретного среза; при новой генерации часы и проценты
меняются (идёт запись открытых блоков), но **логика строк остаётся той же**.

## 6. Проверка перед выдачей

1. Сумма всех строк тела == «Всего» в шапке (допускается расхождение округлением
   до 0.1ч).
2. Сумма процентов ≈ 100%.
3. Ни одного обрезанного названия: каждая строка — либо полное название дела,
   либо первое слово типа с вложенными полными названиями.
4. Одиночные дела не продублированы вложенной строкой.
5. Файл создан, путь к нему назван пользователю.

## 7. Куда писать отчёт

- Временная директория: `C:\Users\ediko\AppData\Local\Temp\opencode\`.
- Имя: `timers-report-<описание (период/назначение/включения)>.md` (например `timers-report-16-09-30-09.md`,
  `timers-report-all.md`,
  `timers-report-хакатоны-2-недели.md`).
- Кодировка UTF-8, переносы `\n`.
- Скрипт-генератор (если создаётся заново) класть рядом, тоже во временную
  директорию; в репозиторий код генерации не коммитить, если пользователь не просил.

## 8. Требования к БД

- Никаких изменений в `src-tauri/`, миграций, пересчётов. Только чтение.
- Если БД не найдена — сообщить путь, который ожидался, и спросить.
- Если пользователь просит изменить данные (переименовать дело, склеить строки в
  самой БД) — это выходит за рамки отчёта: согласовать отдельно.
