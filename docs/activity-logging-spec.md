# Логирование дел + календарь-дашборд — дизайн и план v2.0

Постоянный справочник по фиче «логирование дел и календарь-дашборд». Обновлять при
изменении решений. Краткая шпаргалка — в `AGENTS.md`.

> **Статус**: план. Реализация — будущее.

---

## 1. Общая суть

Таймеры позволяют отслеживать, сколько времени уходит на дела. Каждое «дело» —
именованный отрезок времени. Таймер можно запустить на дело, и всё время его работы
автоматически логируется в базу. На основе данных строится недельный календарь-дашборд
— визуальная полоса дня, размеченная по часам.

**Максимально простая схема**: в календаре только прямоугольники тех промежутков
времени, когда таймер был активен с заданным делом. Больше ничего.

Оценки эффективности/пользы (слайдеры 0–100) — **планы на будущее**, в v2.0 не
реализуются.

## 3. Модель данных (SQLite, схема v2.0)

Хранение — `activity.db` в `app_config_dir()` (рядом с `session.json`). Библиотека
`rusqlite` (features `bundled`).

```sql
CREATE TABLE blocks (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,           -- название дела
  start_ms INTEGER NOT NULL,
  end_ms INTEGER NULL           -- NULL = открыт (таймер идёт)
);
CREATE INDEX idx_blocks_start ON blocks(start_ms);
```

**Только одна таблица, только один тип блока — работа.** Нет `activities`, нет
`break`/`away`, нет `timer_label`. Если таймер активен с делом — блок открыт.
Если таймер встал, окно закрылось, пользователь ушёл AFK или вышел из приложения —
блок закрыт (`end_ms=now`). Пустота = отсутствие логов.

### Инварианты

- Открытых блоков (где `end_ms IS NULL`) — максимум **один** на всё приложение.
- `end_ms >= start_ms` всегда.
- При старте приложения `reconcile()` **удаляет** брошенные открытые блоки
  (если приложение было закрыто некорректно). Не проставляет `end_ms` — удаляет
  строки целиком. Иначе на календаре появится гигантский блок за ночь/день
  вылета, который пользователь не делал.

## 4. Механика логирования

### Когда логируется

Поле дела **не пустое** И таймер **заведён** (running или overtime) → логируем.
Больше никаких условий.

### Начало и конец дела

- **Начало**: таймер заведён/снят с паузы/вернулся с AFK + поле дела непустое →
  `INSERT block` с `end_ms=NULL`.
- **Конец**: таймер встал (пауза/стоп/AFK) → `end_ms=now`. Дело **завершается**.
  Никакого «продолжу завтра».

### Дебаунс названия дела (10 секунд)

Если таймер **уже запущен** (running/overtime) и пользователь меняет название дела в
поле — новое название вступает в силу только через **10 секунд после последнего
изменения текста**.

Зачем: чтобы в логах не появлялись промежуточные варианты (`пр` → `про` → `прое` →
`проект`). Каждое нажатие клавиши сбрасывает таймер. Через 10 секунд молчания —
старое дело закрывается (`end_ms=now`), создаётся новое с введённым именем,
открывается блок.

Правила:
- **До старта таймера** — дебаунса нет. Текст применяется сразу при нажатии «Старт».
- **Во время работы** — дебаунс 10 секунд. Поле визуально показывает текущий ввод,
  но в БД ничего не меняется до таймаута.
- **При очистке поля** — открытое дело завершается. Если поле пустое и
  таймер идёт — логирование не идёт. При этом если запущено несколько таймеров и в одном из них поле очищено а в другом заполнено, то логироваться должен таймер С полем.

### Одно дело одновременно

Поле ввода названия дела видно во **всех** таймерах всегда. Но доступно для ввода
**только в одном** таймере за раз. Правило:

- Если в одном таймере поле заполнено (непустое) — в **остальных** таймерах оно
  становится **серым** (disabled, `pointer-events: none`).
- Если в активном таймере поле очищается — в остальных разблокируется.
- Это обеспечивает инвариант: одно открытое дело на всё приложение.

### AFK

AFK = 2 минуты бездействия (`get_idle_time() >= 120_000`). Механика:

1. Таймер работает, блок открыт.
2. Пользователь ушёл > 2 минут → таймер **останавливается**:
   - `remainMs` перестаёт уменьшаться.
   - Цвет **не меняется**.
   - Блок закрывается (`end_ms=now`). Дело завершается.
3. Пользователь возвращается → таймер продолжает идти, дело продолжается (переоткрывается)

### События

| Событие | Действие |
|---|---|
| Старт таймера / Резюме / Возврат с AFK (дело введено) | `INSERT block` (name, start_ms, end_ms=NULL) |
| Пауза / Стоп / AFK | `end_ms=now` для открытого блока. Дело завершается |
| Закрытие окна / beforeunload / выход | `end_ms=now` для открытого блока |
| Срыв дедлайна | таймер в минус, БД не трогается; блок остаётся открытым |
| Удаление дела | `block_delete` → удалить блок. Если блок открыт — закрыть перед удалением |

## 5. Окно календаря

Открывается **отдельным окном** по кнопке в хабе. Label: `dashboard`.
Обычное (decorated) окно. Навигация — `App.svelte` ветка `dashboard`.

### 5.1. Размер окна

- **По умолчанию**: 2/3 размера экрана (ширина и высота).
- **Динамическое изменение**: при ручном изменении размера (растягивание)
  ширина и высота ячеек пересчитываются пропорционально. Размер шрифта, кнопки
  управления и отступы меню **не меняются**.
- **Сохранение размера**: текущий размер окна сохраняется в `session.json`. При
  повторном открытии календаря открывается с тем же размером.

### 5.2. Верхнее меню

| Элемент | Описание |
|---|---|
| Кнопки управления окном | Стандартные Windows (свернуть, развернуть, закрыть) |
| Показ «Сегодня» | `Сегодня: 09.02` — текущая дата |
| Показ текущей недели | Интервал дат: `08.31 — 09.06` |
| Навигация `<` / `>` | Перемещение по неделям (на 7 дней вперёд/назад) |
| Кнопка «Сегодня» | Вернуться на текущую неделю |

### 5.3. Сетка недели

**7 колонок** — по одной на каждый день недели (пн, вт, ср, чт, пт, сб, вс).

Заголовок колонки:
```
09.02 ср
```
Формат: `ДД.ММ` + сокращённое название дня. День «сегодня» — тёмно-зелёный фон
заголовка.

**Строки** — часовые ячейки с 6:00 до 00:00 невключительно (6:00–23:59).
Разделение — горизонтальные полосы по часам. Получается **18 строк** на каждый день.

Время показано в **боковых метках** (как дополнительные колонки слева и справа от таблицы),
не как полноценные ячейки внутри сетки:
```
    пн  вт  ...  вс
 6  ... ... ... ...  6
 7  ... ... ... ...  7
...
23  ... ... ... ... 23
```
Левая и правая метка времени — дублируют час строки для удобства чтения.

**Динамический размер ячеек**: при изменении размера окна высота ячеек пересчитывается
так, чтобы сетка заполняла доступное пространство. Ширина колонок — равная, по формуле:
`(content_width - time_label_width * 2) / 7`.

### 5.4. Цвета блоков

- Блоки — цвет из детерминированного хеша имени: берём только **hue** (0–360°),
  **насыщенность = 70%**, **светлота = 30%** (в HSL). Так одинаковые имена
  дают один и тот же яркий, различимый цвет.
- Пустые ячейки — фон страницы.

### 5.5. Взаимодействие

- **Клик по блоку** (ПКМ) → контекстное меню с кнопками "редактировать", "удалить". При редактировании popup редактирования: название, время начала, время конца, кнопки
  «Отмена», «Сохранить».
- **Клик по пустой ячейке** (ПКМ) → контекстное меню с одной кнопкой
  «Создать дело». При нажатии — тот же popup: название (пустое), время начала (по
  умолчанию = время кликнутой позиции дня с точностью до минуты), время конца (по умолчанию = +1 час),
  «Отмена», «Сохранить».
- Навигация **только по неделям** (кнопки `<` / `>`).

## 6. Окно таймера — изменения

### 6.1. Поле ввода названия дела

Добавить компактное текстовое поле ввода **над** полем ввода времени. Без отступов,
не расширяет окно. Плоский стиль, как у поля времени.

```
┌────────────┐
│[название]│X│  ← новое поле (текст)
│[   25   ]│🔊│  ← существующее поле (время)
│  24:59   │📌│  ← существующий элемент (оставшееся время)
│▶   ⏸   ■│ │  ← существующие кнопки управления
└────────────┘
существующие закрытие, звук, пин в правой панели
```

### 6.2. Панель справа

В правой панели остаются только:

- **Закрытие** остановка таймера + закрытие окна.
- **Звук** (переключатель beep on/off).
- **Закрепление** (переключатель pinned).

Остальные кнопки по типу "открытие дела" убираются.

## 7. Rust-команды

Все через единый `Mutex<Connection>` в managed state. Регистрировать в `invoke_handler`.

| Команда | Описание |
|---|---|
| `activity_init` | Миграция/инициализация БД. Вызывать при старте |
| `block_open(name, start_ms)` | Открыть блок (INSERT с end_ms=NULL) |
| `block_close(end_ms)` | Закрыть открытый блок (UPDATE end_ms) |
| `block_delete(id)` | Удалить блок |
| `block_update(id, name, start_ms, end_ms)` | Редактирование блока |
| `block_query(from_ms, to_ms)` | Блоки за диапазон |
| `block_suggestions()` | История названий для автодополнения |
| `activity_reconcile()` | Удаление брошенных открытых блоков при старте |
| `get_activity_db_path()` | Путь к БД |
| `create_dashboard_window()` | Окно дашборда |
